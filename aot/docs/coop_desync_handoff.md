# Онлайн-кооп: рассинхрон (Connection Lost) — состояние на 2026-10-07

Документ для продолжения в новой сессии. Ветка `main` (= весь `server_net` + `ultra-optimization`),
последние коммиты: `83023e5` (LOD/LastRenderTime + инструменты), `5640561` (вылет GC), `51ea9de`, `38f8b0a`.

## Проблема

В онлайн-коопе (детерминированный lockstep, см. `online_coop.md`) через 30 с – несколько минут игры
в Ираке (и раньше в Сомали) — «Connection Lost»: контрольная сумма кадра (`cs44` = общий `rand()`,
`cs46` = хэш физики) расходится 600 кадров подряд → клиент выходит.

## Механизм (найден)

Первым всегда расходится **один враг** (`AO2Char_irq05_iraqi_elite_*` / `grunt_*`): его скорость
отличается в младших битах float (напр. `vel C389F50D` vs `C389F3E9`), при этом `rand()`, физика,
игроки, камеры, здоровье, цели ИИ ещё совпадают. Через сотни кадров расходятся позиции → попадание
пули на одной машине → `rand()`/здоровье → контрольная сумма.

Причина — **данные, которые пишет рендер своей машины** (у каждой своя камера), а анимация/движение
врага от них зависят:

1. `SkeletalMeshComponent.PredictedLODLevel` (LOD по экранному размеру) — расхождение `grunt_1`
   точно на кадре, где LOD сменился 1→0 только на одной копии. **Исправлено.**
2. `LastRenderTime` (компонент +624, актор +164; пишет поток рендера в `sub_825560D8`) — следующее
   расхождение совпало с тем, что враг нарисован только на одной копии. **Исправлено.**
3. `SkeletalMeshComponent.LogicalLODLevel` (+1220) — «логический» LOD анимации AO2 (Organiquat),
   на него `ForcedLodModel` не влияет. Считает `sub_827DF400` (из `sub_82624028`) по экранному размеру
   bounds в видах **своей** машины: минимум по видам → `MinDesiredLODLevel` (+1216) и
   `LogicalLODLevel` (+1220). У `elite_4` он был 0 на A и 1 на B на кадре 2160, на 2161 разошлись
   `RootMotionDelta`/`RootMotionVelocity` и скорость. **Исправлено** (`coop_lod.cpp`, 2026-10-07):
   в lockstep оба = 0 после этой функции и на каждом шаге в `ForceLod`. Прогон `local2.sh` после
   этого: три отрезка игры (9363, 4246, 8397+ кадров, пользователь играл бой, гибель → чекпоинт) —
   **контрольная сумма не разошлась ни разу**, пешки совпадают, кроме п. 4.
4. **Лимит трупов — исправлено** (2026-10-08, `coop_ragdoll_pool.cpp`, `ao2_coop_ragdoll_pool_fix`). Пул
   рэгдоллов `AO2GameObjectPool` (`RagdollPool_MaxRagdolls=4`): добавление `sub_822CF838`, при лимите
   `sub_822A2B78` удаляет первые элементы массива (+1136, по 28 байт); тик `sub_822CF900` сортирует их
   по «не виден + дистанция до игроков + время невидимости + возраст», а «виден» — фрустум-тест по видам
   **своей** машины. В lockstep тик получает пустой список видов (порядок — по возрасту и дистанции),
   повторные тики в том же кадре lockstep идут с dt = 0. Удаление нативное, поэтому в строках `D` видно
   только `Destroyed.Pawn`; `--ao2_coop_ragdoll_log=true` → `coop_ragdoll.log` (`R<n>` удаления, `T` пул).
   Прогон `local2.sh`: 9585 кадров, 7 удалений по лимиту — одинаковые на обеих машинах, сумма и пешки
   не разошлись. Остаток в `D`: `SceneCapture2DActor` (`TogglePartnerPIP`, окно напарника) — у машин на
   разных кадрах, на сумму не влияет (локальный вид).
- Прежняя гипотеза про трансформы мешей (`LocalToWorld` и т.п. «с начала уровня») — артефакт:
  `sync_dump.bin` содержит все игры прогона подряд, а `sync_dump_diff.py` смешивал их (теперь
  `--game N`, по умолчанию последняя). Индексы `FName` у машин разные (строки те же, напр.
  `BaseBoneName` = `Gun_Base` под разными индексами) — в дампах это шум.

## Что исправлено (в `main`)

- `aot/src/coop_lod.cpp` (`ao2_coop_force_lod`, по умолчанию вкл.): в lockstep на каждом шаге на обеих
  машинах всем пешкам: `ForcedLodModel = 1` (LOD 0), `bUpdateSkelWhenNotRendered = 1`,
  `bIgnoreControllersWhenNotRendered = 0` (`bTickAnimNodesWhenNotRendered` в этой сборке нет),
  `LastRenderTime` пешки и меша = `WorldInfo.TimeSeconds`. Вызывается из опроса падов (`mouse_aim.cpp`).
  После этого рассинхрон наступает позже, но наступает.
- `decouple.cpp`: после лишних кадров отрисовки откатывается и **поточное** состояние `rand()`
  (`[[r13]+4]`; в коопе игровой поток берёт его, а не общий `[0x830AB53C]`). Оказалось не причиной
  (в отрисовке `rand()` не вызывался), но правильно.
- **Вылет при загрузке уровня** (`sub_82481B18` null+12 в сборке мусора, «дисконнект до уровня»):
  запоздалые результаты occlusion-запросов писались в освобождённую и переиспользованную память
  (проверка смотрела только маркер 0xFFFFFEED). Теперь пишутся только если все 32 байта структуры
  совпадают со снимком на момент конца запроса (`renderer.cpp`, `5640561`). Это же было
  «нерешённое падение в GC при 120 FPS» из CLAUDE.md.
- `ao2_coop_god_mode` (`cheats.cpp`): бессмертие обоим игрокам на обеих машинах (для тестов; должно
  совпадать у обоих). Сейчас включено строкой в `aot/settings/hardware.toml` (не закоммичено) и в
  `hardware.toml` на ПК партнёра.
- Предсказание камеры для мыши (`ao2_predict_camera`, `interp_camera.cpp`/`mouse_aim.cpp`) — только
  отрисовка; в коопе на рассинхрон не влияет (камеры в логах совпадают).

## Что исключено

- **Развязка рендера и симуляции** (`ao2_decouple`): с `--ao2_decouple=false` рассинхрон тоже есть.
- **Задержка ввода (lead):** `[+260]`/`[+212]` считаются из записей кадров, одинаковы на обеих машинах.
- **Процессоры AMD/Intel:** `frsqrte`/`fres`/`vrsqrtefp`/`vrefp` эмулируются точно (1/sqrt, 1/x).
- **`rand()` в лишних отрисовках:** счётчик `draw` в трассировке = 0.
- **Камеры игроков:** `cloc`/`crot`/FOV совпадают до самого расхождения.
- **Решения ИИ:** указатели (PathToGoal, RealRouteGoal…) указывают на одни и те же по имени объекты.
  Адреса объектов у машин разные с запуска (даже UClass) — это норма, указатели в дампах = шум.
- Скриптовые прогоны без боя/без камеры не воспроизводят на двух ПК; на одном ПК (`local2.sh`)
  воспроизводится даже стоя (окно B почти ничего не рисует — видимость сильно разная).

## Инструменты

- `--ao2_coop_sync_trace=true` → `sync_trace.log` (строки `F` контрольные суммы/rand/игроки/камеры,
  `R` кто брал `rand()`, `P` все пешки: loc/rot/vel/hp, `V` видимость: LastRenderTime/LOD).
  `D` — `Destroy()` акторов (кадр, имя, скрипт).
  `python tools/sync_diff.py <A> <B> [--cs XXXX]` — первый разошедшийся кадр/пешка (сам находит одну
  игру в логах: самую длинную общую, или ту, что начинается с контрольной суммы `--cs`, напр. `4AE1` —
  начало Ирака; после гибели уровень с чекпоинта начинается снова с той же суммы).
- `--ao2_coop_sync_dump=N` → `sync_dump.bin` (сырая память пешки/меша/контроллера врагов каждые N
  кадров); `python tools/sync_dump_diff.py <A> <B> --game N --before FRAME` (в файле все игры прогона
  подряд, `--game` — какая; без него — последняя).
- `python tools/ue3fields.py <pid> <ИмяПешки> pawn|mesh|controller <смещения…>` (или
  `class:<адрес>`) — имена полей по смещению в запущенной игре. `aot/src/ue3_reflect.cpp` —
  поиск смещений свойств по имени в рантайме (`PropertyOffset`, `BoolProperty`). Раньше поиск
  делал `VirtualQuery` на каждый объект и занимал минуты (главный поток стоял на старте уровня,
  отсюда `hang_*.dmp`); теперь проверенные регионы кэшируются на время поиска.
- **Сборка:** `cmake --build out/build/win-amd64-release` перезаписывает `rexruntime.dll` в папке игры
  стоковым из `aot/rexglue` — без сетевых правок SDK кооп не работает («No Connection» при входе в
  Public Co-op). После сборки копировать `sdk/out/win-amd64/Release/rexruntime.dll` в папку игры.
- `--ao2_start_checkpoint=05_10` в одиночной игре падает (`XamShowDirtyDiscErrorUI`, abort
  `C0000409`); `05_100` работает — годится, чтобы быстро получить живых врагов Ирака для `ue3fields.py`.
- **Воспроизведение на одном ПК:** `bash tools/coop/local2.sh` (две копии: A хост 127.0.0.1, B
  клиент 127.0.0.2, папки `tools/coop/local/A|B` с копией профиля), через ~45 с
  `bash tools/coop/local2.sh menus` (Ирак, Start Game). Рассинхрон за 1–2 мин. `EXTRA="--ao2_…"` —
  доп. флаги обеим. Логи в `tools/coop/local/A|B/`.
- Два ПК: `tools/coop/auto_coop.sh` (макрос меню; навигация `tools/coop/nav.py` по
  `iraq_route.txt` ненадёжна у перил/укрытий). ПК партнёра: `ssh -i ~/.ssh/ao2_partner_ed25519
  admin@192.168.31.88`, игра в `C:\aot2\aot\out\build\mn` (и `win-amd64-release`), там же
  `AO2_launcher.cmd` (пользователь запускает сам; по файлу `launch_host.request` стартует хост).
  Создавать задачи планировщика/пускачи там Claude не разрешено. `git fetch` по SSH у партнёра не
  работает (учётка GitHub в Credential Manager) — exe копировать через scp.
- Логи большие: `sync_trace.log` ~1 ГБ/час — забирать хвост, не целиком.

## Прочее замеченное

- Брифинг Ирака кнопкой A не пропускается полностью (~2,5 мин до уровня); магазин в начале — B.
- В `local2.sh` B стартует через 20 с после A: иначе B ждёт сервер EA с чёрным экраном 30+ с.
- Мышь: `mx500` поворачивает на ~7750 единиц (вдвое больше расчёта при чувствительности 2.0).
